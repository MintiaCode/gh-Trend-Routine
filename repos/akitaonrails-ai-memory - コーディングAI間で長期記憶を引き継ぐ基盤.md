# akitaonrails/ai-memory

▎ コーディングAI間で長期記憶を引き継ぐ基盤

言語: Rust

---
## 概要

ai-memoryは、Claude CodeやOpenAI Codex、Cursorなど異なるAIコーディングエージェント間でセッションを跨いだ長期記憶を実現するRust製のツールである。従来、エージェントを切り替えたりセッションを再開したりするたびに、プロジェクトのアーキテクチャや過去の試行錯誤を毎回説明し直す必要があり、コンテキストの再構築に多くの時間が浪費されてきた。ai-memoryはフック機構によって作業中の観察内容を自動的かつ最小限の手間で記録し、セッション終了時にそれらを要約して次のエージェントへの「引き継ぎ」情報として提供する。保存形式にはベクトルDBではなくGit管理されたプレーンなMarkdownウィキを採用しており、grepで検索したりObsidianで閲覧したり、rsyncでバックアップしたりできる点が特徴である。SQLiteベースのFTS5全文検索とエンティティ抽出により、LLMを使わずとも高精度な検索が可能。対象ユーザーは、複数のAIコーディングツールを併用する開発者や、長期プロジェクトでのコンテキスト散逸に悩むエンジニアリングチームである。

---
## 主な機能・特徴

- セッション間引き継ぎ — フックが観察内容を自動記録し、次のエージェントセッションへ要約を引き継ぐ
- マルチエージェント対応 — Claude Code、Codex、Cursor、Gemini CLIなど多様なコーディングエージェントをMCP経由でサポート
- Markdownウィキ保存 — ベクトルDB不要、Gitでバージョン管理された人間可読なMarkdownとして記憶を保存
- ゼロLLM検索 — FTS5全文検索とエンティティ抽出により、LLMなしでも高精度な想起が可能
- 権威ベースの想起 — 確定したルールや意思決定を、断片的な経験的証拠より優先して提示
- 単一バイナリのRust実装 — MCP/HTTPサーバーを1つのバイナリで提供し、Docker/ネイティブ両対応
- 除外設定 — リポジトリ単位で特定ファイル・ツールイベントのキャプチャを除外可能
- 読み取り専用ブラウザUI — 保存されたウィキ内容をブラウザから閲覧できるビルトインUIを搭載

## トレンド入り理由の推測

今日1日で+207スターという伸びは、累計2,000スター程度の比較的新しいリポジトリとしてはかなり急激な増加であり、話題化の初期段階にあると考えられる。README中の「Quit Claude Code mid-task, start OpenAI Codex in the same directory, continue without re-explaining the architecture」という一文は、AIコーディングエージェントを日常的に使う開発者の間で強く共感を呼ぶ具体的なユースケースを提示しており、これがSNSや開発者コミュニティでの言及・拡散に直結した可能性が高い。

2026年半ばの時点でClaude Code、Codex、Cursor、Gemini CLIなど複数のAIコーディングエージェントを併用する開発スタイルが一般化しつつあり、「エージェントを乗り換えるたびにコンテキストを失う」という課題は多くの開発者が経験している痛点である。ai-memoryはこの隙間にRust製の軽量な単一バイナリとして入り込み、ベンダーロックインなしに横断的な記憶レイヤーを提供する設計が、特定ベンダーに依存したくない開発者層から支持を集めやすい。またベクトルDBを使わずMarkdown+FTS5というシンプルな構成を選んだことも、運用コストや透明性を重視するエンジニアに刺さりやすく、MITライセンスでの公開と合わせて導入障壁の低さがトレンド入りを後押ししたと考えられる。
