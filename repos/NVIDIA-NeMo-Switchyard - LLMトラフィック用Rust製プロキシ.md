## 概要

Switchyardは、NVIDIAが開発するRust製のプロキシ兼ライブラリで、複数のLLMプロバイダーをまたいでリクエストをルーティングするために作られている。OpenAI Chat形式・Anthropic Messages形式・OpenAI Responses形式の相互変換に対応しており、異なるAPI仕様のモデルプロバイダーを意識せずに切り替えられる点が大きな特徴である。ルーティング方式としては、リクエスト内容からティアを判定する「LLM Classifier」、会話内のツール結果などの既存シグナルを利用する「Stage Router」、まず弱いモデルで処理し判定モデルが必要に応じて強いモデルへエスカレーションする「Escalation Router」、固定比率でトラフィックを振り分けるRandomルーティングの4方式が用意されている。Prometheus形式の運用メトリクスも収集でき、Claude Codeなどのコーディングエージェントと統合するランチャー方式、スタンドアロンのプロキシとして動くサーバー方式、Rustアプリケーションに組み込むライブラリ方式の3通りの利用形態を選べる。現時点ではpre-alpha段階であり本番利用は非推奨とされているが、複数モデル・複数プロバイダーを使い分けたいLLMアプリケーション開発者やインフラエンジニアが主な対象ユーザーとなる。

---
## 主な機能・特徴

- マルチプロバイダー対応 — OpenAI Chat / Anthropic Messages / OpenAI Responses形式を相互変換
- LLM Classifierルーティング — リクエスト内容からティアを判定
- Stage Router — 会話中のツール結果など既存シグナルを活用
- Escalation Router — 弱いモデルで処理後、判定モデルが強いモデルへの昇格を判断
- Randomルーティング — 固定比率のトラフィック分割によるテスト用
- Prometheusメトリクス — 運用状況をメトリクスとして収集
- 3つの利用形態 — ランチャー/スタンドアロンサーバー/Rustライブラリから選択
- Claude Code等との統合 — コーディングエージェントのランチャーとして利用可能

## トレンド入り理由の推測

NVIDIAという大手ブランドが手がける新規プロジェクトである点がまず注目を集めやすい要因だが、それ以上に「複数のLLMプロバイダーを横断してルーティングする」というテーマ自体が、2026年現在のAI開発トレンドと強く一致している。OpenAIとAnthropicの両API形式を相互変換できる機能は、単一プロバイダーへのロックインを避けたい、あるいはコストや性能に応じてモデルを動的に使い分けたいという開発者ニーズに直接応えるものであり、複数のフロンティアモデルが乱立する現在の状況下で強い実用性を持つ。

さらに、「Escalation Router」のように弱いモデルでまず処理し必要な場合のみ強いモデル(かつ高コスト)へエスカレーションする設計は、LLM APIコストの最適化という多くの企業が直面する課題への具体的な解決策を提示しており、技術的な目新しさと実務上の即効性を兼ね備えている。Claude Codeなどコーディングエージェントとの統合を明示している点も、AIコーディングツールの利用が急拡大する中でのタイムリーな訴求と言える。まだpre-alpha段階のRust製プロジェクトでありながらこれだけの支持を集めているのは、NVIDIAブランドの信頼性とこの技術的方向性の実需の両方が背景にあると考えられる。
